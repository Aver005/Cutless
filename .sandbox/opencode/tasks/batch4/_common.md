# Общие правила (читай внимательно, нарушать нельзя)

Ты — исполнитель в проекте **Cutless**: форк нативного видеоредактора Concat на Rust 2024 + Slint.
Твоя текущая папка — отдельный git worktree с полной копией репозитория. Cargo-workspace лежит в `src/`:
все команды `cargo` запускай из `src/`. Окружение сборки (FFmpeg, libclang, ONNX Runtime) уже выставлено
в переменных среды, общая папка сборки — `CARGO_TARGET_DIR`. Не меняй эти переменные.

Перед работой прочитай: `CLAUDE.md`, `.memories/CONVENTIONS.md`, и код, который будешь менять, целиком.

## Можно
- Менять только файлы, перечисленные в твоей задаче (и создавать новые файлы там, где задача разрешает).
- Запускать `cargo check -p <крейт из задачи>` (можно `--tests`) и `cargo fmt -p <крейт>` из `src/`.
- Читать любые файлы, в том числе исходники зависимостей в `~/.cargo/registry/src/`.

## Нельзя
- `cargo build`, `cargo test`, `cargo clippy`, `cargo run`, запуск приложения — это делает интегратор.
- `git commit`, `git push`, `git checkout`, `git branch`, `git reset`, `git stash` — никаких git-операций, меняющих историю или ветки.
- Добавлять зависимости, кроме явно разрешённых в задаче.
- Трогать файлы вне задачи, переформатировать чужой код, переименовывать то, что не просили.
- `unwrap()`/`expect()` в новом коде вне тестов, `unsafe`, `Result<_, String>` в публичных функциях новых модулей.
- Удалять SPDX-шапки. Новые файлы Cutless начинай с шапки:
  `// SPDX-License-Identifier: AGPL-3.0-or-later` и `// SPDX-FileCopyrightText: 2026 Cutless contributors`.

## Стиль
- В новых файлах Cutless комментарии и doc-комментарии на **русском**, простыми словами, не длиннее двух строк.
- В существующих файлах апстрима — стиль и язык соседнего кода (английский).
- Ошибки — через `thiserror`. Всё повторяющееся — в функцию. Код читаемый без длинных пояснений.
- Пиши юнит-тесты на новую логику (их запустит интегратор).

## Отчёт
В конце обязательно запиши отчёт в файл `{{OUT}}` (на русском):
1. Что сделано (кратко). 2. Список изменённых и созданных файлов. 3. Решения, которые ты принял сам, и почему.
4. Последние строки вывода `cargo check` (успех или ошибки). 5. Что не доделано, риски, вопросы интегратору.
Если не уверен — сделай самый простой корректный вариант и опиши сомнение в отчёте, а не выдумывай.

## Общее для инструментов агента (пачка 4)
Каркас — `src/crates/cutless-tools/src/lib.rs` (прочитай целиком, НЕ меняй без крайней нужды; если без правки никак —
минимальная, опиши в отчёте). Инструмент = структура, реализующая `Tool` (`spec()` + `call()`), регистрация — в
`register(registry)` своего модуля. Запросы редактору — `ctx.call(concat_api::Request::...)` (ответ — JSON ответа API).
Типы запросов — `src/crates/concat-api/src/message.rs`; правки документа — `Request::EditApply { path, command }` с
`concat_project::Command` (`src/crates/concat-project/src/commands/mod.rs`). Правила инструментов (подробно —
`.memories/reference/AI-LAYER.md`): мелкие понятные операции; ответ — короткий текст для модели (что изменилось, новые
id), а не весь проект; время во входе и выходе — секунды; описание и схема входа — по-английски, doc-комментарии в
коде — по-русски. На каждый инструмент — тест разбора входа и хотя бы один тест поведения через тестовый `Editor`
(отвечает заранее заданными `Response`) или через настоящий `concat_api::Api` на временной папке.
Связанные правки одного вызова — одним `Command::Batch` (один шаг undo). Прямой записи `concat.json` не бывает.
