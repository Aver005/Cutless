# LEARNINGS
> Грабли и неочевидные факты. Last updated: 2026-10-16.

Факты собраны чтением кода апстрима `v0.2.7-21-gef49577`. Что проверено только чтением, а не запуском,
помечено `[?]`.

## Сборка

- **`cargo` только из `src/`.** Корень git — не корень Cargo; из корня команды падают с непонятными
  ошибками путей.
- **`FFMPEG_DIR` задаётся в окружении машины, не в `src/.cargo/config.toml`.** Комментарий в этом файле
  прямо запрещает: путь машины в репозитории ломает чужие сборки.
- **На Windows DLL FFmpeg должны быть в `PATH`**, иначе тесты и окно не стартуют. Нужна именно сборка
  `win64-gpl-shared`: статическая `ffmpeg-master-latest-win64-gpl` (стоит у владельца в `E:\Apps\ffmpeg`)
  не подходит — в ней нет заголовков и `.lib`.
- **Кроме FFmpeg сборке на Windows нужны** libclang (bindgen), cmake (whisper.cpp), ONNX Runtime
  (`ORT_LIB_LOCATION` + `ORT_PREFER_DYNAMIC_LINK=1`) и библиотеки sherpa-onnx (`SHERPA_ONNX_LIB_DIR`).
  README апстрима упоминает только FFmpeg, полный список — в `ci.yml`. Всё это ставит
  `scripts/cutless/win-deps.sh`.
- **cmake на машине владельца есть только внутри Visual Studio** (Community 2022 и Build Tools на `H:`),
  в `PATH` его нет. libclang, 7-Zip и `python3` нет; Python запускается как `python`.
- **`skia-bindings` во время сборки качает готовый Skia с GitHub.** Это происходит для каждого профиля
  (`quick` и `dev` — разные папки в `target/`). Если сеть мигнула, build-скрипт пытается собрать Skia из
  исходников и падает. Лечится повторным запуском при живой сети. Код ошибки — в логе: `curl error code: "6"`.
- **Профили `quick` (окно, `cargo dev`) и `dev` (clippy, тесты) собираются отдельно.** Первый clippy после
  первого `cargo dev` снова компилирует все зависимости.
- **У LLVM для Windows есть портативный архив** `clang+llvm-*-x86_64-pc-windows-msvc.tar.xz` (~940 МБ).
  Из него достаточно вытащить `bin/libclang.dll`, установщик с правами администратора не нужен.
- **`.slint` компилируется в потоке со стеком 512 МБ** (`src/crates/concat/build.rs`). На Windows
  компилятор Slint иначе падал с переполнением стека. Не «упрощать».
- **`rustc` падает с `0xc0000409` (STATUS_STACK_BUFFER_OVERRUN) на крейте окна** в профиле `dev` (тесты): код,
  сгенерированный Slint, переполняет стек компилятора. Лечится `RUST_MIN_STACK=536870912`, он теперь в
  `vendor/env.sh` (`scripts/cutless/win-deps.sh`). Без него `cargo test -p concat` не собирается (2026-10-16).
- **Обновление Slint = ручной перенос патча** `src/patches/i-slint-renderer-skia` (ClearType, глифы).
  Без переноса текст на Windows станет мыльным.
- **`cargo dev`** = `run --bin concat --profile quick`. Движок с оптимизацией, окно без, инкрементально.
  Первый билд — минуты, это нормально.

## Тесты

- **CI апстрима гоняет тесты через `cargo nextest` — каждый тест в отдельном процессе.** Обычный `cargo test`
  гоняет тесты крейта в одном процессе и вскрывает то, что nextest прячет (две сессии ONNX, `BUGS.md`).
- **`cargo test --workspace` включает фичи по объединению workspace:** `concat-vision` идёт с `infer` (ONNX).
  `cargo test -p concat-vision` — без неё, поэтому тестов меньше (26 против 31).
- **`every_edit_still_exports` апстрим на Windows гоняет отдельно** — он зависал. Пропускать в общем прогоне:
  `cargo test --workspace -- --skip every_edit_still_exports`. `CARGO_PROFILE_DEV_DEBUG=0` ускоряет линковку.
- **Время на машине владельца:** сборка тестов + прогон `--workspace` — 13,5 мин с нуля; `concat-render` —
  50 с параллельно и 145 с в один поток.
- **`ort-sys` сам кладёт `onnxruntime.dll` жёсткой ссылкой рядом с бинарниками** (`target/*/deps`), поэтому
  заглушка `C:\Windows\System32\onnxruntime.dll` (2019, 2,8 КБ) не мешает. Копировать руками не нужно.
- **Тесты с сетевым сервером в потоке зависают, если клиент жив при `join`** (2026-10-16, `cutless-mcp/remote.rs`):
  сервер теста читает, пока клиент не отключится, а тест ждёт сервер. Перед `handle.join()` — `drop(editor)`.
  Подвисший тестовый exe держит файл, и следующая сборка падает с `LNK1104`. Тесты исполнителей гонять с `timeout`.
- **Консоль Windows у владельца в cp1251.** Python-скрипты, печатающие не-ASCII, переключают stdout на UTF-8.

## API и команды

- **README апстрима обещает MCP, а его нет.** Есть только комментарий в `concat-api/src/lib.rs`, что
  MCP — будущий транспорт. Это наша Ф2.
- **API-сервер не правит проект, открытый в окне.** Так задумано (`OpenProjects`/`Holder`). Для живой
  работы агента нужен мост (Ф3), а не «просто включить Remote».
- **`edit.apply` возвращает весь `Project`.** Для агента это дорого по токенам: нужны компактные ответы.
- **`UpdateClip` заменяет цепочки `filters`/`video_effects` целиком**, а `SetEffectKey` адресует эффект
  по индексу. Агент с устаревшим состоянием затрёт чужие эффекты. Лечится ревизиями и id (Ф2.3, Ф2.4).
- **Экспорт через API всегда VBR и без выбора аппаратного энкодера.** CBR и аппаратный выбор есть только в окне.
- **Сценарий API работает «из коробки»:** `scripts/cutless/api-smoke.py` проходит 10 шагов за 5 с. Горизонтальный
  клип в проекте 9:16 вписывается с чёрными полями (fit) — заполнение кадра требует рефрейма (Ф5.1).
- **id медиа и клипов выдаются при создании** (`m1`, `c2`, …) и приходят в `createdId` ответа. Статичный JSONL
  без подстановки id не работает — нужен скрипт.
- **`concat-cli serve` по умолчанию пишет только в домашнюю папку** (`--root`), токен печатает при
  старте или берёт из `CONCAT_API_TOKEN`.
- **JSON-схем для `Command` нет** (`schemars` не подключён). Схемы инструментов придётся писать или
  генерировать — новая зависимость (Р10).

## Модель документа

- **Типов дорожек нет**, все универсальные. «Главной дорожки», как в CapCut, тоже нет.
- **Субтитры — обычные текстовые клипы** (`AddTextClip` пачкой в `Batch`), отдельной дорожки нет.
- **Whisper отдаёт сегменты без времени слов** (`Segment {start, end, text}`). Караоке и монтаж по
  словам требуют доработки (Ф5.5) `[?]`.
- **Анимации текста апстрим удалил сознательно:** `drop_retired_fields` вычищает старые поля при
  открытии проекта. Возвращать их полями клипа нельзя — только пакетами (`DECISIONS.md`).
- **`DOCUMENT_VERSION = 1` заморожен**, миграции формы клипов не решены. Новые данные — в `extra`.
- **Переход хранится на клипе** (`transition_in`), а не между клипами.

## Идентичность

- **`IDENTIFIER = "app.concat.editor"` определяет пути данных.** Пока он не сменён, Cutless и Concat
  делят настройки, кэш и проекты пользователя (`reference/REBRAND.md`).
- **Модели и обновления идут с репозитория апстрима**, пока не сменены `REPO` в `models.rs` и `updates.rs`.

  дольше ~45 с — долгое уходит в фоновую задачу (`reference/AI-LAYER.md` → Долгие задачи).
- **Клиент сокета окна обязан читать его всё время.** Сервер апстрима кладёт события в очередь на 256 строк и
  при переполнении забывает подписчика; молчащий между вызовами клиент терял `export.done` (2026-10-16, исправлено
  потоком чтения в `cutless-mcp/src/remote.rs`).
- **Живой прогон pooprusteek без его настоящих данных:** `pooprusteek --data-dir <папка> exec --mcp -C <папка> ...`,
  в `<папка>/mcp.json` — свой сервер и `overrides` с `enabled: false` для чужих (Cursor и др.), иначе подключаются все.

## Отладка падений окна

- **Адрес падения из лога** (`crash: ... in concat.exe+0x…`) разрешается в функцию:
  `vendor/llvm/bin/llvm-symbolizer.exe --obj=src/target/quick/concat.exe --relative-address 0x…`
  (символизатор вынут из архива LLVM в `vendor/dl/llvm.tar.xz`; PDB профиля `quick` лежит рядом с exe).
- **Лог окна** — `%LOCALAPPDATA%pp.concat.editor\logs\concat-*.log` (пока не сменён идентификатор).
- **Сравнение с официальной сборкой без установки:** `msiexec /a Concat-…msi /qn TARGETDIR=<папка>` распаковывает
  MSI, exe запускается из `PFiles64\Concat`. Так за минуту видно, виноват код после релиза или машина.
- **Бэкенд wgpu на Windows жёстко DX12** (`concat/src/gpu.rs`): Skia собран только под D3D, Vulkan окну недоступен,
  `WGPU_BACKEND` ничего не меняет.
- **Скриншоты окна — через `PrintWindow(PW_RENDERFULLCONTENT)`**, не с экрана: окно может быть перекрыто.
  Скрипт съёмки в нескольких размерах — `shoot.ps1` (черновая папка сессии; при надобности перенести в `scripts/cutless/`).
- **Playwright MCP не открывает `file:`** — для проверки HTML поднимать `python -m http.server`.

## Ключи и удары

- **`SetClipKey`/`SetEffectKey` склеивают ключи ближе `KEY_EPSILON` = 0,002 доли клипа.** На клипе 60 с это 0,12 с
  (3,6 кадра при 30 fps): ключи «на каждый кадр» молча схлопываются. Частые ключи — только `SetKeySpan`.
- **Ключи — доли длины клипа.** Смена скорости меняет длину и растягивает ключи; `SetClipSpeed` при этом ключи не
  перепривязывает (обрезка и разрез — перепривязывают). Поэтому сначала скорость, потом удары.
- **Звено цепочки без явного значения играет умолчание пакета**, а модель его не знает (`value_at` просит fallback).
  Умолчание берётся из каталога (`ParamInfo.default`).
- **`SetClipSpeed` сам снимает кривую скорости и при замедлении сдвигает следующие клипы дорожки;**
  `SetClipSpeedCurve` не сдвигает ничего.
- **У слоя-обработки трансформа нет, `frame.clip_time` в шейдере всегда 0** (`concat-render/src/gpu.rs`). Движение
  слоя — только ключами параметров (`cutless.camera`), одноразовое — тоже ключами, не временем.

## Пакеты эффектов

- **`sample()` нельзя вызывать внутри ветки, зависящей от пикселя** (это `textureSample`). Читать до `if` или через
  `sample_premultiplied` (без производных, результат предумножен).
- **Сэмплер — только ClampToEdge.** Сдвиги за край отражаются в шейдере: `1 - abs(1 - fract(q*0.5)*2)`.
- **Пробы шейдеров на программном адаптере молча пропускаются.** Гонять с `CONCAT_REQUIRE_GPU=1`:
  `cargo test -p concat-render every_package_probe_holds`.
- **`locales.py --check` не падает на пропущенных переводах**, только на устаревших ключах и неактуальном `en.json`.
- **Два пакета не могут заменять (`[[replaces]]`) один и тот же старый id** — построение каталога паникует.

## Интерфейс

- **`accessible-label` в Slint ставится только вместе с `accessible-role`** — иначе ошибка сборки окна.
  У примитива `Button` своей разметки доступности нет: на экземпляре — `accessible-role: button` и подпись.
- **Правка из инспектора идёт через эхо клипа:** `set(ClipField, value)` меняет эхо, `commit_now` сравнивает
  клипы в `clip_commands` и выпускает команды. Новое поле клипа, не сравниваемое там, молча теряется.

## Сетка долей

- **Контраст «доля минус полудоля» врёт на эдитах:** хэт на «и» делает полудоли сильными, и побеждает сетка через
  полторы доли (128 → 85,3). Счёт — «доли выше среднего по треку» плюс опора на полудоли.
- **Опору на полудоли надо ограничивать:** у полутемпа «полудоли» — настоящие доли, такие же сильные; без штрафа
  метроном 128 читается как 64.
- **Автокорреляция может дать пунктирный темп** (DnB 174 → 116): кандидаты включают ×3/4 и ×4/3, иначе 87 и 174
  не рассматриваются вовсе.
- **Классифицировать удары по онсетам в логарифме нельзя:** подъём из тишины в любой полосе выглядит большим, малый
  и хэт становятся «бочками». Только по мощности полос.
- **Новизна громкости тактов — квадратами разностей:** сумма модулей одинакова для резкой границы и размазанной на
  два такта, и сильная доля выбирается наугад.
- **Онсет огибающей опережает удар на полшага** (окно сглаживания видит подъём раньше) — 5 мс поправки.

## Агенты DeepSeek (OpenCode)

- **Общая папка данных OpenCode на нескольких параллельных исполнителях → `database is locked`** (SQLite), и
  исполнитель падает сразу. Лечение — своя папка данных на каждого: `DS_DATA=.sandbox/opencode/.data/<задача>`
  (так делает `batch.sh` с 2026-10-16). В исходных скриптах владельца (`minecraft-copy/.sandbox/opencode`) та же
  проблема — там она не проявлялась, видимо, из-за разнесённого старта.
- `batch.sh` пропускает задачу, если её отчёт непустой; упавшие оставляют пустой отчёт — перезапуск идёт отдельной
  папкой заданий (`tasks/<пачка>-retry`), чтобы не продублировать живого исполнителя.
- **`TaskStop` фоновой обёртки `batch.sh` не убивает исполнителей OpenCode** — они дорабатывают и пишут отчёты.
  Ждать их по появлению отчётов и выходу процессов `opencode`, а не перезапускать пачку (2026-10-16).
- **Исполнители не пишут в локали:** каждый кладёт `locales-<задача>.json`, интегратор сливает
  `.sandbox/opencode/merge-locales.py` — иначе 25 JSON-файлов конфликтуют при слиянии веток.
- **Панель OpenCode (`panel.sh`) 2026-10-17 не дала ни одного ревью за три попытки:** первый запуск трёх моделей
  разом сломал общую базу OpenCode (гонка миграции, `FOREIGN KEY … workspace`); две модели 12 минут читали дифф на
  2700 строк и упёрлись в 30-минутный лимит, не записав итог; повторные запуски висели на старте и падали с кодом 127.
  Задания для панели — узкие, с требованием писать находки в файл по ходу; при трёх сбоях — Claude-агенты.
