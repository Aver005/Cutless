## 0. Коротко

1. **concat — серьёзная основа.** Около 95 тыс. строк Rust и 30 тыс. строк Slint, GPU-превью, FFmpeg, whisper, TTS, вырезание фона, HDR, сборки под пять платформ. Проекту меньше двух месяцев, его почти целиком пишет один человек, и он очень быстро развивается.
2. **Для ИИ-слоя в concat уже готова половина.** Каждая правка проекта — сериализуемая JSON-команда (`Command`) с undo. Над командами есть транспортно-независимый `concat-api` с JSON-RPC-сервером и CLI. **MCP-сервера нет**, хотя README его обещает. В коде он прямо запланирован как «ещё один транспорт».
3. **ki-video по возможностям — небольшое подмножество concat.** Переносить его код не нужно: другой язык (TS против Rust) и другой рендер (граф ffmpeg против GPU-композитора). Переносить стоит **сценарий**: рефрейм ShadowPlay в 9:16 жестами в превью, авто-ключи, пресеты «ТикТок» и звука.
4. **econcar показывает, что нужно агенту:** таймлайн как текст, время в долях такта, проверка через отдельные кадры и контакт-листы, анимированный текст, пакеты стилей. Половины этих примитивов в concat нет: бит-сетки, анимаций текста (их **убрали**), контакт-листов, «умных» команд.
5. **pooprusteek подключается к concat без правки своего кода** — как MCP-клиент к MCP-серверу редактора. Встраивать его библиотекой сейчас дорого: крейт только бинарный и конфликтует с concat по версии `ort`.
6. **Юридически форк возможен, но с условиями.** Лицензия AGPL-3.0, исходники открыты. **Название и логотип «Concat» использовать нельзя**: форк обязан называться иначе и иметь свою иконку.

**Рекомендуемый путь:** мягкий форк, то есть держаться близко к апстриму. ИИ-слой — отдельные крейты, минимум правок в чужих файлах. Начать с MCP-сервера над `concat-api` и **предложить его в апстрим**: это одновременно экономит силы на поддержку и даёт тот самый «респект».

## 1. Погружение в concat

### 1.1. Что это и на чём сделано

- **Язык.** Rust, edition 2024, toolchain закреплён на `1.93.1` (`src/rust-toolchain.toml`).
- **Интерфейс.** Используется **Slint 1.18.1** — декларативный UI-язык (`.slint`-файлы) с биндингами в Rust. Это не веб, не Tauri, не Electron и не Qt. Рисует **Skia** поверх **wgpu 30**, окно — через winit.
- **Видео.** FFmpeg 7+ подключён **как библиотека** (`ffmpeg-the-third`), а не внешним процессом, как в ki-video. Звук идёт через `cpal`.
- **ML** работает полностью локально:
  - whisper.cpp (`whisper-rs 0.16`) делает субтитры;
  - sherpa-onnx (Kokoro, Pocket TTS) и ONNX Runtime (`ort =2.0.0-rc.13`) дают озвучку и клонирование голоса;
  - RVM, ISNet и SlimSAM вырезают фон;
  - Real-ESRGAN делает апскейл.
- **Платформы.** Windows, macOS, Linux, Android и iOS (мобильная оболочка `ui/phone/*`).

**Как устроен UI в двух словах.**
- Корень интерфейса — `src/crates/concat/ui/app.slint`; Slint компилирует его в Rust при сборке (`build.rs`).
- Логика написана в стиле Elm: колбэк из Slint превращается в сообщение `Msg`. Его принимает контроллер `Studio::handle` (`src/crates/concat/src/studio.rs`), затем `pane.update`, затем `publish()` пересобирает модели для Slint.
- Панели (`panes/*.rs`) устроены по одной схеме: `state + Msg + update + data`.
- Документ меняется **только** через команды движка, поэтому undo работает везде.
- Окно и GPU-композитор делят одно wgpu-устройство, так что кадр превью — это текстура без копирования в CPU.

**Темы.** Все цвета лежат в `ui/theme/` (`dark.slint`, `light.slint`, `accent.slint`), и нигде больше цвета не задаются. Ребрендинг внешнего вида — правка одной папки.

**i18n.** Строки берутся по ключу: `I18n.t("area.name")`. Локали — `src/crates/concat/locales/*.json`, всего 25 языков, русский есть. Проверка — `scripts/locales.py --check`.

**Горячие клавиши.** `KeyBinding` в `ui/app.slint`, список — `docs/KEYBOARD_SHORTCUTS.md`.

Cargo-workspace лежит в `src/`, а не в корне репозитория. **Все команды `cargo` нужно запускать из `src/`.**

### 1.3. Модель проекта

Модель лежит в `src/crates/concat-project/src/model.rs`.

- **`Project`** — медиатека, шрифты и **несколько таймлайнов**.
- **`Timeline`** — настройки видео (размер, fps, SDR/HLG/PQ), дорожки и плоский список клипов.
- **`Track`** — только `id`, `visible` и `muted`. **Типов дорожек нет**, все универсальные. «Главной дорожки», как в CapCut, тоже нет.
- **`Clip`** — центральная структура:
  - вид: `Video | Audio | Image | Text | Layer | Shape`;
  - время: `start`, `duration`, `source_start`;
  - звук: громкость, фейды;
  - трансформ: scale, offset, rotation, stretch, flip, opacity, blend;
  - скорость и кривая скорости;
  - crop, cutout (маска);
  - цепочки `filters` (аудио) и `video_effects`;
  - `transition_in`: переход хранится на клипе;
  - стили текста и фигуры.
- **Ключевые кадры** бывают двух видов:
  - на свойствах клипа: Scale, OffsetX, OffsetY, Rotation, Opacity, Volume;
  - на любом параметре эффекта.

  Сглаживание — кубическая кривая Безье.
- **Субтитры** — это обычные текстовые клипы, отдельной дорожки нет.
- **Файл проекта** — `concat.json`, camelCase, `DOCUMENT_VERSION = 1`. Неизвестные поля сохраняются, запись атомарная.

### 1.4. Команды и undo — то, на чём строится ИИ-слой

`Command` (`concat-project/src/commands/mod.rs`) — enum с `#[serde(tag = "op")]`. Каждая правка — JSON вида `{"op":"splitClips", ...}`.

Какие операции есть:

- **Медиатека:** `AddMedia`, `RemoveMedia`, `UpdateMediaPath` (переподключение), `FillSlot` (шаблоны).
- **Размещение:** `AddClip`, `AddTextClip`, `AddShapeClip`, `AddLayerClip`.
- **Монтаж:** `MoveClips`, `TrimClip {ripple}`, `SplitClips`, `MergeClips`, `RemoveClips {ripple}`, `FreezeFrame`, `DetachAudio`, `ReplaceClipMedia`.
- **Скорость:** `SetClipSpeed`, `SetClipSpeedCurve`.
- **Свойства:** `UpdateClip {patch}`, `SetClipTransform`.
- **Ключи:** `SetClipKey`, `SetEffectKey` и их очистка.
- **Дорожки и таймлайны:** `AddTrack`, `SetTimelineVideo` и другие.
- **`Batch`** — атомарная группа команд, один шаг undo.

**Undo** хранит до 200 шагов. Снимки делят данные через `Arc`, поэтому копируется только изменённый клип. Жесты склеиваются в один шаг (`apply_within` / `end_gesture`).

### 1.5. Медиа, превью, экспорт

- **Прокси.** Для источников крупнее HD делается H.264-копия; она нужна только для воспроизведения. Экспорт и превью на паузе читают оригинал.
- **Превью.** Чистая функция `plan_frame(t)` строит план кадра, wgpu-композитор его рисует. Без GPU работает программный адаптер: WARP или lavapipe. **Часы воспроизведения — счётчик сэмплов звуковой карты**, картинка следует за звуком.
- **Экспорт.**
  - Тот же композитор, затем readback, затем энкодер.
  - Кодеки H.264, HEVC и AV1. Энкодеры: x264/x265/SVT-AV1, NVENC, QSV, AMF, VideoToolbox, MediaCodec.
  - Поддерживаются 10 бит и HDR.
  - Контейнер только MP4.
  - **9:16 есть** (1080×1920), пресетов под площадки нет.

### 1.6. Что уже есть для автоматизации

| Поверхность | Где | Что даёт |
|---|---|---|
| `concat-api` | `src/crates/concat-api/src/{lib,message}.rs` | Методы `project.*`, `edit.{apply,undo,redo}`, `media.{probe,import}`, `catalogue.list`, `template.*`, `export.{run,cancel}` + события, `preview.frame` (PNG). **`edit.apply` принимает любой `Command`** |
| `concat-server` | `src/crates/concat-server/` | JSON-RPC 2.0 построчно через TCP или Unix-сокет. 128-битный токен, ограничение путей для записи. gRPC за фичей |
| `concat-cli` | `src/crates/concat-cli/src/main.rs` | `concat-cli api` — JSON-RPC через stdin/stdout (готовый headless-режим), `serve` на `127.0.0.1:7420` |
| Remote в настройках окна | `panes/settings.rs` | Сервер внутри запущенного приложения. **Он не может править проект, открытый на экране** — это сделано намеренно |

JSON Schema для `Command` не генерируется: `schemars` нет.

### 1.7. Сборка и запуск

## 2. ki-video против concat

### 2.1. Что такое ki-video

- Bun-сервер + React 19 + shadcn (React Aria) + Tailwind v4, FSD, свой стор на `useSyncExternalStore`.
- ffmpeg вызывается внешним процессом.
- Около 12,5 тыс. строк, 26 коммитов за 7–8 сентября 2026, 66 тестов на чистые функции.
- Один сценарий: горизонтальная запись ShadowPlay → окно 9:16 с панорамой и зумом по ключам → цвет, звук, текст, субтитры → H.264/H.265.

### 2.2. Сравнение

| Аспект | ki-video | concat |
|---|---|---|
| Стек | TS, Bun, React, браузер в режиме `--app` | Rust, Slint, Skia, wgpu, нативное окно |
| Превью | Скрытый `<video>` на каждый клип + canvas, синхронизация с допуском 0,5 с | GPU-композитор, часы — звуковая карта, точно до кадра |
| Экспорт | Один большой граф `filter_complex`, ключи превращаются во вложенные `if()` | Тот же композитор, что в превью, и энкодер |
| Модель | content / overlay / audio, `frame` и `box` в одном типе | Универсальные дорожки, единый `Clip` |
| Ключи | Линейные, ключ — снимок всех полей | Безье на каждое свойство и на любой параметр эффекта |
| Undo | 100 полных `structuredClone` | 200 снимков с разделением через `Arc` |
| Переходы | Наезд клипов = xfade, 9 видов, в превью не видны | 20 пакетов-шейдеров, видны в превью |
| Цвет и звук | Только на весь проект | На каждый клип, 57 фильтров, 25 аудиоэффектов |
| Текст и субтитры | 3 пресета, анимации fade и pop, импорт SRT | Богатая стилизация, автосубтитры whisper. **Анимаций нет, SRT нет** |
| ИИ | Нет | Whisper, TTS, вырезание фона, апскейл |
| API для агента | REST: только PUT всего проекта, без событий об изменениях | Команды + JSON-RPC + CLI + `preview.frame` |
| Платформы | Windows | 5 платформ |

**Вывод.** По функциям concat покрывает ki-video почти полностью. В обратную сторону мало что есть: SRT, анимации текста fade и pop, кнопка «ТикТок-пресет».

### 2.3. Что из ki-video стоит перенести (идеи, не код)

1. **Сценарий рефрейма 9:16.** Тянешь по превью — двигается центр окна, колесо — зум, `K` — ключ. Логика `setFrame` сама решает, править неподвижное значение или ставить ключ в текущий момент. В concat это ложится на `SetClipTransform` и `SetClipKey(Scale/OffsetX/OffsetY)`. Нужен режим «рефрейм» в превью с жестами.
2. **Математика окна кадра** (`ki-video/src/core/frame.ts`): `baseWindow`, `frameToRegion`, `clampFrame` прижимают окно к краям, а если окно шире исходника — центрируют. Её стоит переписать на Rust как утилиту «перевести центр и зум в scale и offset клипа».
3. **«Быстрый ТикТок-пресет»** — одна кнопка, которая выставляет 9:16, цвет, звук и субтитры. В concat это `Batch` из готовых команд, удобно и для агента.
4. **Звуковые пресеты «Голос чисто» и «Игра громко»**: highpass, шумодав, компрессор, loudnorm. В concat есть `loudnorm` и `enhance voice` как отдельные пакеты, не хватает только готовых цепочек.
5. **Пресеты субтитров и импорт SRT.**
6. **Привычка вести `.memories/` и DECISIONS.** Апстрим и так ведёт `ARCHITECTURE.md` и `audit/`, их стоит дополнять.

Не переносить: плеер превью, сборку графа ffmpeg, стор, интерфейс. В concat всё это сделано лучше.

## 3. econcar: как монтирует агент и что из этого следует

### 3.1. Как это устроено

Ролик — это **код на Remotion** (React → кадры → h264). Методика зафиксирована в навыке `C:\Users\Aver\.claude\skills\promo-reel\`. Та же схема повторяется в `VibeCuts\me\diary`, то есть это устойчивый процесс, а не разовая работа.

Как шёл econcar:

1. **Исследование продукта.** Снимки сайта, токены бренда, шрифт, проверка фактов.
2. **Музыка.** Скрипт `tools/audio.py` режет трек мини-языком операций (`seg:A:B`, `sil:S`, `tape:A:S`, `fade:S`). Затем подбирает bpm и фазу и находит удары по полосам (бочка, малый, общий). Результат — `src/tracks/*.json`.
3. **Сюжет.** `makeStory({grid, cuts[7], silence, ...})` превращает секунды в кадры и даёт `beats`, `kicks`, `drop` и `beatsIn(scene)`.
4. **Текст** лежит отдельно, в `copy.ts`. **Звуковые подсказки** привязаны к долям: `at: beatsIn('fuel')[1] - 2`.
5. **Четыре стиля** (`variants/*.tsx`) на одном сюжете: Brand, Dashcam, Cluster, News.
6. **Проверка.** `remotion still` → контакт-лист 4×2 → агент смотрит картинку → правит. Финальный рендер, затем мастеринг по LUFS с поправкой задержки AAC.
7. **Критики-субагенты** (моушн, синхронизация с музыкой, тексты) — по навыку. Их отчётов в папке нет, поэтому то, что они запускались, — предположение.

**Роли:**
- Человек даёт продукт и формат, выбирает стиль, делает вкусовые замечания.
- Агент делает всё остальное, включая разметку звука.

### 3.2. Почему это работает с любой неглупой моделью

- **Таймлайн — это текст.** Его можно читать, грепать, сравнивать по diff.
- **Детерминизм.** Всё выводится из номера кадра, случайность — с seed. Любую правку можно проверить точечно.
- **Время в музыкальных единицах.** Модель рассуждает «вторая доля сцены», а не «кадр 143». При смене трека всё пересчитывается само.
- **Проверка через отдельные кадры.** Модель со зрением смотрит контакт-лист. Без зрения работает числовая сверка склеек с сеткой.
- **Анализ звука вынесен в скрипты.** Модель получает таблицу, а не аудио.
- **Опыт накоплен в навыке.** Раздел «Грабли» предупреждает о типичных ошибках заранее.

### 3.3. Ограничения

- Нет интерактивного таймлайна: сдвинуть надпись на 3 кадра — значит править TSX с магическими координатами.
- Полный рендер занимает минуты.
- Контакт-лист не показывает плавность движения.
- **Навык не работает с живым видео как с материалом** (нарезка дублей, цвет, голос). А это как раз сильная сторона concat.

### 3.4. Примитивы, которых редактору не хватает для такой работы

| Примитив | Есть в concat? |
|---|---|
| Проект как JSON + атомарные команды + undo | **Да** (`Command`, `Batch`) |
| Отдельный кадр по запросу | **Да** (`preview.frame`) |
| Контакт-лист (N кадров в сетку с номерами) | Нет, легко собрать поверх `preview.frame` |
| Музыкальная сетка как сущность проекта (bpm, фаза, удары по полосам), привязка к долям | **Нет**, бит-детекция есть только в запросах пользователей |
| Сборка музыки операциями (seg, sil, tape-stop, fade) | Нет, частично можно монтажом клипов |
| Ducking (приглушение) и громкость кривой по кадрам | Ключи громкости есть, автоматического дакинга нет |
| Анимированный текст (пословное появление, печатание, счётчик) | **Нет**: пресетные анимации текста **убрали** в апстриме |
| Пульс и тряска на ударе как модификатор свойства | Нет |
| Пакеты стилей (токены бренда + сюжетный конфиг → сцены) | Частично: шаблоны со слотами |
| Транскрипт с таймкодами для агента | Whisper есть в окне, **в API нет**. Таймкодов по словам нет |
| Линтер безопасных зон TikTok, длины текста, «пустого первого кадра» | Нет |
| Headless-рендер и CLI | **Да** (`concat-cli render`, `api`) |

Отсюда видно, где форк может быть **по-настоящему уникальным**: соединить живое видео (сила concat) с музыкально-ритмическим монтажом агентом (сила econcar). Ни у одного из двух проектов по отдельности этого нет.

## 4. pooprusteek: что даёт для форка

### 4.1. Кратко

- TUI-агент на Rust (tokio + ratatui), **переписанный poopseek**.
- 75 тыс. строк, 180 коммитов с 25.06 по 30.09.2026, около 1230 тестов, CI на трёх ОС.
- Основной бэкенд — **веб-API chat.deepseek.com**: токен из localStorage, PoW решается оригинальным WASM сайта через wasmtime, SSE с родным «Продолжить». Дополнительно работают OpenAI-, Anthropic- и Gemini-совместимые провайдеры.
- **Вызов инструментов без нативного function calling.** Формат `<tool_use>` задаётся в промпте. Парсер `src/agent/tool_parser/` понимает почти все известные форматы (DSML DeepSeek, Hermes, Claude-подобный…), у вызовов есть уровни доверия.
- Есть MCP-**клиент** (stdio, HTTP, SSE, OAuth), отложенные схемы + `tool_search`, локальный RAG, суб-агенты, режим GOAL.
- Режимы без TUI:
  - `exec` — агент как подпроцесс с трассой JSONL;
  - `--serve`/`--proxy` — OpenAI-совместимый шлюз, который **эмулирует `tools` для DeepSeek Web**.
- `--acp` — **заглушка**, несовместимая с ACP Зеда. Полноценный ACP был в TS-версии poopseek.

### 4.2. Варианты интеграции

| Вариант | Оценка | Что нужно |
|---|---|---|
| **(a) concat поднимает MCP-сервер, pooprusteek подключается клиентом** | **Лучший старт** | В pooprusteek — ничего. В concat — крейт `concat-mcp`. Тот же сервер сразу работает с Claude Code, Gemini CLI и Cursor |
| (b) Харнесс встроен в concat как библиотека | Дорого сейчас | Вынести `pooprusteek-core` (крейт только бинарный, цикл агента завязан на `app::*`). Разрулить конфликт `ort` rc.12 и rc.13 (одинаковый `links = "onnxruntime"`). Тяжёлые зависимости: wasmtime, tokio |
| (b′) concat запускает `pooprusteek --proxy` подпроцессом | Дёшево, но грубо | Свой небольшой цикл агента в concat поверх OpenAI API. Без состояния, токены тратятся на всю историю каждый раз |
| (c) concat — ACP-клиент с чат-панелью, агенты внешние | Отличный UI-слой, продолжение (a) | Чат-панель в Slint, ACP-клиент. В pooprusteek — настоящий `--acp` по образцу `poopseek/src/acp/server/` и `harness/driver.rs` |

**Важное ограничение для видео.** У DeepSeek Web **нет зрения**: из вложений он только извлекает текст, а MCP-клиент pooprusteek сводит картинки к строке `[Image: mime]`. Поэтому агенту на DeepSeek нужно давать **текстовое** описание происходящего: таймлайн, транскрипт, удары музыки, числовые проверки. Для визуальной проверки контакт-листами нужна модель со зрением (Claude, Gemini) через тот же MCP.

## 5. Синтез: каким может быть форк

### 5.1. Идея продукта в одной фразе

**Нативный редактор уровня CapCut, которым может управлять любой агент через открытый протокол, с инструментами для ритмического и вертикального монтажа.** Человек монтирует руками, агент — командами, и оба работают с одним проектом и видят правки друг друга.

### 5.2. Архитектура ИИ-слоя

```
 ┌──────────── агенты ────────────┐
 │ pooprusteek  Claude Code  Gemini CLI  Cursor │
 └──────┬──────────────┬──────────┘
        │ MCP (stdio/HTTP)   │ ACP (чат-панель в окне, этап 4)
 ┌──────▼──────────────▼──────────┐
 │ concat-mcp   — инструменты, компактные ответы, схемы │  ← новый крейт
 │ concat-agent — «умные» команды: рефрейм, вырезать паузы, │  ← новый крейт
 │                бит-сетка, контакт-лист, линтер        │
 ├──────────────────────────────────┤
 │ concat-api  (Request → dispatch → Response + Event)   │  ← есть, дополнить глаголами
 │ concat-project::Command + undo                        │  ← есть
 └──────────────────────────────────┘
        ▲ мост «правка проекта на экране» (этап 3) ─ concat (окно, Studio)
```

**Принципы:**
- Новое живёт в **своих крейтах**. В `studio.rs` и чужие файлы — минимум точечных правок. Так проще подтягивать апстрим.
- Агент **никогда** не пишет `concat.json` напрямую, только команды. Получаем undo, валидацию и живое обновление окна.
- Ответы агенту **компактные**: дифф или текстовая сводка таймлайна, а не весь `Project`. Сейчас `edit.apply` возвращает документ целиком, это дорого по токенам.
- Всё, что агент «видит», дублируется текстом, чтобы работали модели без зрения.

### 5.3. Этапы

**Этап 0. Освоиться (1–2 недели).**
- Собрать `cargo dev` на Windows, пройтись по `ARCHITECTURE.md`, `src/README.md`, `audit/AUDIT-2026-10-12-QUICK.md`.
- Руками через `concat-cli api` выполнить цепочку `project.create`, `media.import`, `edit.apply` (`splitClips`…), `preview.frame`, `export.run`. Это проверка, что API реально рабочий.
- Выбрать имя и иконку, завести ветку под ребрендинг: идентификатор, URL обновлений, зеркало моделей.

**Этап 1. MCP-сервер (`concat-mcp` + `concat-cli mcp`).**
- Инструменты по группам: `project_*`, `media_import`, `timeline_summary` (компактная текстовая сводка), `clip_split`, `clip_trim`, `clip_move`, `add_text`, `set_transform`, `set_key`, `apply_effect`, `catalogue_search`, `preview_frame`, `export_*`, `undo`/`redo`.
- Проверить с pooprusteek (`/mcp add`) и с Claude Code.
- **Предложить PR в апстрим**: в README обещан MCP, а в коде под него оставлено место. Принятый PR даёт репутацию и снимает с тебя поддержку этого слоя.
- Нужна новая зависимость `schemars` для схем — или схемы руками.

**Этап 2. Глаголы и «умные» команды.**
- Вынести из окна в `concat-host`/`concat-api`: `captions.transcribe`, `transcript.get`, `speech.synthesize`, `cutout`, `enhance`, `reverse`.
- Свои крейты:
  - **бит-сетка** — порт идей `tools/audio.py` на Rust или вызов внешнего скрипта;
  - **контакт-лист**;
  - **рефрейм в 9:16** — математика из ki-video;
  - **вырезать паузы и слова по транскрипту**;
  - **линтер безопасных зон и длины текста**.
- Исправить два места, опасных для агента:
  1. `UpdateClip` **полностью заменяет** цепочки эффектов;
  2. `SetEffectKey` адресует эффект по индексу.

  Нужны адресация по стабильному id или проверка `revision`, иначе агент с устаревшим состоянием затрёт эффекты.

**Этап 3. Живой мост к окну.**
- Внешние `edit.*` идут в `Studio::apply` через `slint::invoke_from_event_loop` (новый `Msg::Agent`).
- Агент правит проект **на экране**, у человека работает Ctrl+Z.
- Это самая рискованная правка (`studio.rs` на 11 тыс. строк, гонки с жестами пользователя), поэтому она идёт после того, как отработан headless-режим.

**Этап 4. Чат-панель и ACP.**
- Панель по шаблону `panes/export.rs` + `ui/workspace/agent-pane.slint`.
- Внутри — ACP-клиент: агент запускается подпроцессом и получает MCP редактора через `session/new`.
- Параллельно в pooprusteek сделать настоящий `--acp`.

**Этап 5. Моушн-слой в духе econcar.**
- Вернуть анимации текста как пакеты с ключами: пословное появление, печатание, счётчик.
- Модификатор «пульс на ударе».
- Пакеты стилей поверх шаблонов со слотами.
- Это уже фичи для людей, которыми агент пользуется так же, как человек.

### 5.4. Риски

| Риск | Чем грозит | Что делать |
|---|---|---|
| Апстрим очень быстрый (сотни коммитов в месяц) | Жёсткий форк сгниёт за пару месяцев | Мягкий форк, свои крейты, регулярный rebase/merge, отдавать общее в апстрим |
| Bus factor апстрима = 1 | Апстрим может замереть | Тогда форк становится основной веткой, и это нормально, если ты в коде освоился |
| Порог Rust и Slint | Slint — новый для тебя UI-язык | Первые этапы (MCP, команды) не требуют Slint вообще |
| Сборка на Windows (FFmpeg dev, cmake, whisper, sherpa) | Первый билд может занять день | Следовать `src/README.md`, BtbN-сборка FFmpeg |
| DeepSeek Web — неофициальный API | Ломается без предупреждения; вероятно, против ToS (не проверял) | В форке не завязываться на конкретного агента. MCP/ACP — открытые протоколы, DeepSeek — одна из опций |
| Позиционирование «ничего не уходит с диска» | Облачный LLM ему противоречит | Агент — внешний и опциональный, по умолчанию выключен, явно разрешаются локальные модели |
| AGPL | Все изменения форка открыты | Это и есть цель. Закрытое можно держать только во внешних плагинах через API |
| Формат проекта v1 заморожен | Новые поля (бит-сетка, анимации) ломают совместимость | Сначала хранить в `extra`, повышение версии согласовывать с апстримом |

### 5.5. Решения, которые нужно принять тебе

1. **Имя и иконка форка** — без этого нельзя публиковать сборки.
2. **Мягкий или жёсткий форк.** Рекомендую мягкий, с активным контрибьютом в апстрим (MCP — первый кандидат).
3. **Какие агенты в приоритете.** Если DeepSeek без зрения — этап 2 (текстовые сводки, транскрипт, числовые проверки) важнее контакт-листов.
4. **Нужна ли чат-панель внутри окна** или хватит внешнего агента (Claude Code / pooprusteek в терминале рядом). Второе в разы дешевле и покрывает 80% пользы.
5. **Куда двигать продукт:** «агентный CapCut» вообще или узкая ниша «вертикальные ролики из игровых записей и промо под музыку» (то, что ты реально монтируешь). Ниша даёт более сильное позиционирование при запуске.
